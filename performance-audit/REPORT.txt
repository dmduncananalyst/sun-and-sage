DOMMYDOM PERFORMANCE AND SOURCE-LINK AUDIT
October 14, 2026 — local changes only; no commit, push, or publication.

What caused the loading delays
The shared photo-navigation-ready.js intercepted normal link clicks, fetched the destination HTML, and waited for all selected destination/card images to download and decode before navigating. There was no timeout. A slow image could hold visitors on the old page indefinitely. Hovering also downloaded many destination photos, competing with current-page resources.
Pages referenced between 32 and 97 separate stylesheets. Many successive local stylesheets could be combined without changing their cascade. Galleries and category pages eagerly loaded dozens of photos, and some offscreen photos were preloaded at high priority. Several large PNGs could be compressed losslessly. Missing intrinsic image dimensions also provided an avoidable layout-stability risk, although the baseline sample pages measured zero CLS.

Corrections
Normal navigation now proceeds immediately. Optional document-only prefetching is capped at four destinations, uses deliberate mouse hover/keyboard focus, and is disabled for reduced-data/2G connections. It does not preload destination photos or intercept clicks.
Combined successive compatible local stylesheets into 72 reusable, content-hashed bundles. Inline-style boundaries, stylesheet attributes, imports, and rule order are preserved. Relative CSS asset URLs are rebased. Original CSS files remain available. HTML base URLs on nested articles are respected. Total stylesheet references across 351 pages fell from 28,798 to 15,801, about 45%. Source CSS is loaded synchronously to avoid an unstyled link flash.
Images beyond the first three main-content images use native lazy loading. Removed high-priority preloads for later photos and homepage photos below the video. Added absent intrinsic dimensions and asynchronous decoding. Existing responsive crops, layouts, photographs, video sources/posters, autoplay, animations, and interactive features are retained. Existing script ordering and font families/loading behavior are preserved.
Added six lossless WebP candidates using srcset; original src URLs/files remain as fallbacks. Dimensions, ICC profiles, and every decoded RGBA pixel were verified against the original PNGs. Combined savings: 5,101,452 bytes. No resizing or lossy recompression was used.
Added shared source-reference-links.css and a scoped class to the existing reference sections. The changes provide subdued brand colors, a visible underline, subtle hover treatment, and visible keyboard focus. Source names, wording, typography, section layouts, and destinations are unchanged. No buttons or decorative panels were added.

Sources and resources
All 269 reference sections and all 635 reference entries already contained functioning HTML anchors with href attributes; the primary presentation problem was absent visible link treatment. There were no unlinked entries requiring invented or replacement URLs.
There are 100 distinct external destinations and four distinct internal neighborhood-guide destinations. Direct HTTP checks retrieved 70 external destinations. Web retrieval confirmed another 25 after direct requests encountered access, certificate, or timeout failures. Five destinations remain incompletely verified: the California legislative Civil Code 5551 page; California Courts divorce, property/debts, and probate pages; and the old www2.laparks.org park directory. Courts/directory destinations have supporting official search-index or PDF evidence, but direct retrieval did not succeed. The old park-directory request has a certificate/hostname mismatch. Their existing href values were retained rather than guessing replacements. See UNVERIFIED-SOURCES.txt for every affected page and source-verification.json for all results. A direct 404 for consumer.gov's budget article was contradicted by successful exact-URL web retrieval, so its existing official URL was correctly retained.

Checks not completed / practical limits
This is a local laboratory comparison, not a deployed speed guarantee, Lighthouse score, or field Core Web Vitals measurement. Individual timing observations varied. Baseline HTML was supplied from the unchanged Git HEAD while baseline assets used the local server; the optimized HTML/assets used the local server. No remote hosting/cache/compression configuration was changed or tested.
External scripts and fonts were blocked during local rendering/performance tests. Live Google font behavior, analytics delivery, HubSpot/backend submissions, and chat submission delivery were not exercised. Existing script/font code was preserved; local chat opening/closing was tested. No claim is made that all external services were verified.
Mobile tests used a 390px Chrome viewport rather than a physical phone. Safari, Firefox, other browsers, and every possible viewport were not tested. Six representative pages received full visual comparisons; every reference page received focused desktop/mobile CSS checks, and all 351 pages received static preservation checks.
Five external source destinations remain incompletely verified, as detailed above. No inaccurate replacement links were created.
